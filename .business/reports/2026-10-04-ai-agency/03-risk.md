## 1. 쟁점별 검토

### 1-1. 개인정보보호법: 처리위탁 수탁자로서의 의무

**누가 무엇인가 (A 기준)**
- 구매자 개인정보(이름, 연락처, 주소, 주문 내역)의 **개인정보처리자 = 셀러**. 오픈마켓이 판매자에게 배송 목적으로 넘긴 정보다.
- 창업자가 셀러 대신 그 데이터를 받아 서버에서 처리하면 **처리위탁의 수탁자**가 된다(제26조).
- 창업자가 쓰는 VPS, 구글 시트, LLM API = 수탁자가 다시 맡기는 **재위탁**이다. 재위탁하려면 **위탁자(셀러)의 동의가 필요하다**(제26조 제6항).
- B도 고객사 시스템 안에 고객·직원 개인정보가 있으면 똑같이 수탁자가 된다.

**위탁계약서 필수 조항 (제26조 제1항, 시행령 제28조)**: 아래 내용을 **문서로** 정해야 한다.
1. 위탁업무 수행 목적 외 개인정보 처리 금지
2. 기술적·관리적 보호조치
3. 위탁업무의 목적과 범위
4. 재위탁 제한
5. 개인정보 접근 제한 등 안전성 확보 조치
6. 위탁업무와 관련해 보유한 개인정보의 관리 현황 점검 등 감독
7. 수탁자가 의무를 위반했을 때의 손해배상 등 책임
- 출처: [스타트 법무법인 — 처리위탁 필수 계약조항](https://www.startlawfirm.com/blog/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4-%EC%B2%98%EB%A6%AC-%EC%9C%84%ED%83%81-%EC%B1%85%EC%9E%84-%EA%B4%80%EB%A6%AC%EA%B0%90%EB%8F%85/), [서울시교육청 위탁 계약 자료(PDF)](https://www.sen.go.kr/resources/www/data/infoprotect_3_10.pdf)
- **셀러 쪽 의무**: 셀러는 수탁자(창업자)와 위탁 업무 내용을 **자기 개인정보 처리방침에 공개**해야 한다. 소규모 셀러는 대부분 자체 처리방침이 없다. 창업자가 공개 문구 템플릿을 같이 주는 것이 좋다(고객 리스크가 결국 창업자에게 돌아오기 때문).

**수탁자가 직접 지는 책임 (2023 개정 이후)**
- 2023 개정으로 제26조 제8항이 안전조치(제29조), 유출 통지·신고(제34조), **과징금(제64조의2)** 등을 수탁자에게 준용한다. 수탁자도 과징금·과태료·형사처벌의 직접 대상이다. 출처: [보안뉴스 — 처리위탁 개정 취지](http://www.boannews.com/news/articleView.html?idxno=137496), [김·장 — 개정안 정무위 통과](https://www.kimchang.com/ko/insights/detail.kc?sch_section=4&idx=26311)
- **과징금**: 일반 상한은 **전체 매출액의 3%**(매출이 없거나 산정하기 어려우면 20억원 이하).
- **2026-09-11 시행 개정법(법률 제21445호, 2026-03-10 공포)**: 3년 안에 고의·중과실로 반복 위반, 고의·중과실로 1,000만명 이상 피해, 시정명령을 어겨 같은 유출 재발 시 **최대 10%**. 대표자 최종 책임 명문화, "유출등" 정의에 위조·변조·훼손 추가. 예방 투자 시 최대 40% 감경. 출처: [법률신문(율촌) — 10% 과징금·대표자 책임](https://www.lawtimes.co.kr/news/articleView.html?idxno=226414), [블로터](https://www.bloter.net/news/articleView.html?idxno=673291), [헤럴드경제](https://biz.heraldcorp.com/article/10870442), [Lexology](https://www.lexology.com/library/detail.aspx?g=6b427fc1-9b0d-4acc-9050-3be555103842)
  - 1인 사업자에게 10% 요건(1,000만명 피해 등)이 걸릴 가능성은 낮다. **현실적인 위험은 과징금보다 손해배상**이다. 법정손해배상은 1인당 300만원 이하(제39조의2), 고의·중과실이면 손해액의 최대 5배(제39조 제3항) **(법령 원문 확인 필요)**. 구매자 1,000명 주소록이 유출되면 산술상 최대 30억원이다. 셀러가 이 손해를 창업자에게 구상한다.
- **형사**: 수탁자가 위탁 범위를 넘어 개인정보를 이용하거나 제3자에게 제공하면 형사처벌 대상이다(제71조 등) **(법령 원문 확인 필요)**. 예: 셀러 A의 구매자 데이터를 셀러 B 분석이나 다른 상품 마케팅에 쓰는 것.
- **유출 시 절차**: 1,000명 이상 유출, 민감·고유식별정보 유출, 외부 불법 접근에 의한 유출이면 **72시간 안에** 정보주체 통지와 개인정보위·KISA 신고를 해야 한다 **(시행령 원문 확인 필요)**. 수탁자는 위탁자에게 **즉시** 알려야 한다. 이 내용을 계약서에 시한(예: 인지 후 24시간)으로 박는다.

**안전성 확보조치 (「개인정보의 안전성 확보조치 기준」 고시, 2025-10-31 개정 시행, 2026-07-01 시행분 있음)**
- 개정 요지: 외부에서 개인정보처리시스템에 접속할 때 안전한 인증수단(MFA 등)을 적용해야 하는 대상이 "정당한 접근권한을 가진 자" 전체로 확대됐다. 접속기록 보관 대상도 "시스템에 접속한 자" 전체로 확대됐다. 일률적인 망분리는 위험 기반 보호로 바뀌었다. 출처: [법률신문(김·장)](https://www.lawtimes.co.kr/news/articleView.html?idxno=213530), [CELA](https://www.cela.kr/4/?bmode=view&idx=168696184), [intothesec — 2025.11 안내서](https://intothesec.com/157)
- 1인 사업자가 실제로 할 것(최소 세트):
  1. 서버·DB·n8n·구글 계정에 **MFA**. SSH는 키 인증만, 비밀번호 로그인 끄기.
  2. 셀러별로 API 키·토큰을 **비밀 저장소**(환경변수 암호화, 1Password/Vault 등)에 분리해 보관. 코드·시트·채팅에 키를 붙여넣지 않는다.
  3. 개인정보 필드(이름, 전화, 주소)를 **암호화 저장**하거나 아예 저장하지 않기(아래 가명처리).
  4. **접속기록**(누가 언제 어떤 데이터에 접근했나)을 최소 1년 보관하고 월 1회 점검 **(보관 기간은 고시 원문 확인 필요. 정보주체 5만명 이상이나 민감정보면 2년)**.
  5. 셀러별 데이터 **논리 분리**(테넌트 분리). 셀러 A 워크플로가 셀러 B 데이터를 못 읽게 한다.
  6. 보관 기간을 정하고 자동 파기(예: 원본 주문 데이터 90일, 집계만 보존).
  7. 한 페이지짜리 **내부관리계획**과 사고 대응 절차를 만든다. 고객 여러 곳의 구매자를 합치면 금방 1만명이 넘는다. 소상공인 면제를 기대하지 않는 것이 안전하다 **(추정)**.

### 1-2. 해외 클라우드·LLM API로 보낼 때의 국외이전

- 제28조의8: 개인정보를 국외로 **제공·처리위탁·보관**(조회 포함)하려면 별도 동의, 또는 "계약 이행을 위한 처리위탁·보관으로서 이전 국가·업체·항목·목적 등을 처리방침에 공개하거나 알린 경우" 같은 예외 요건이 필요하다. 해외 클라우드 저장은 보통 위탁이자 국외이전으로 본다. 출처: [중기이코노미 — 해외서버 이용](https://www.junggi.co.kr/news/articleView.html?idxno=32298), [nepla — 해외 클라우드 일문일답](https://www.nepla.ai/wiki/it-%EC%A0%95%EB%B3%B4-%EB%B0%A9%EC%86%A1%ED%86%B5%EC%8B%A0/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4-%EC%9C%84%EC%B9%98%EC%A0%95%EB%B3%B4-%EC%8B%A0%EC%9A%A9%EC%A0%95%EB%B3%B4/-%EC%9D%BC%EB%AC%B8%EC%9D%BC%EB%8B%B5-%ED%95%B4%EC%99%B8-%ED%81%B4%EB%9D%BC%EC%9A%B0%EB%93%9C-aws-%EB%93%B1-%EC%97%90%EC%84%9C-%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EB%A5%BC-%EB%B3%B4%EA%B4%80-%EC%B2%98%EB%A6%AC%ED%95%A0-%EB%95%8C-%EC%A0%95%EB%B3%B4%EC%A3%BC%EC%B2%B4%EC%9D%98-%EB%8F%99%EC%9D%98%EB%A5%BC-%EB%B0%9B%EC%95%84%EC%95%BC-%ED%95%98%EB%8A%94%EA%B0%80-54gnvzpe81pr), [개인정보위 — 생성형 AI 개인정보 처리 안내서(2025.8)](https://smartcity.go.kr/wp-content/uploads/2025/09/%EB%B3%84%EC%B2%A82-%EC%83%9D%EC%84%B1%ED%98%95-%EC%9D%B8%EA%B3%B5%EC%A7%80%EB%8A%A5AI-%EA%B0%9C%EB%B0%9C%C2%B7%ED%99%9C%EC%9A%A9%EC%9D%84-%EC%9C%84%ED%95%9C-%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4-%EC%B2%98%EB%A6%AC-%EC%95%88%EB%82%B4%EC%84%9C.pdf)
- **실무상 문제**: 국외이전 공개 의무를 지는 주체는 처리자인 셀러다. 하지만 셀러 처리방침에는 창업자가 쓰는 미국 LLM API가 적혀 있지 않다. 공개 없이 보내면 셀러가 위반하고, 창업자는 재위탁 동의 없는 재위탁으로 위반한다.
- **Anthropic API 사실관계** (원문 확인): 상업용 API 데이터는 명시적 허락 없이 학습에 쓰이지 않는다. 대화 내용은 기본적으로 보관하지 않지만, 일부 지정 모델("Covered Models")은 **30일 보관이 필수**다. ZDR(무보관)은 별도 계약 대상이다. **Claude Code 로컬 세션 기록은 조직 설정에 따라 장기 보관될 수 있다**(Compliance API 기준 기본 6년). 출처: [Claude Platform Docs — API and data retention](https://platform.claude.com/docs/en/manage-claude/api-and-data-retention)
  - **B에 특히 중요**: 고객사 코드·DB 덤프·로그를 Claude Code로 작업하면 그 내용이 해외로 전송된다. **고객사의 서면 동의 없이 하면 국외이전·비밀유지 위반 소지**가 있다.

**권장 설계: "개인정보가 LLM에 가지 않는 구조"**
1. **A의 리포트·정산·재고 작업은 원래 개인정보가 필요 없다.** 주문번호, 상품코드(SKU), 수량, 금액, 수수료, 배송 상태만 있으면 된다. API 응답을 받는 즉시 이름·전화·주소·배송메모 필드를 **버리는(drop) 단계**를 파이프라인 첫 노드에 둔다.
2. 구매자를 구분해야 하면(재구매율 등) 구매자 ID나 전화번호를 **셀러별 비밀키로 HMAC 해시**해서 가명 ID로만 저장한다. 해시 키는 셀러별로 분리하고 데이터와 다른 곳에 보관한다. 이것은 가명처리(제2조 1의2)에 해당한다. 단, 가명정보도 개인정보이므로 안전조치 의무는 남는다.
3. LLM에는 **집계 숫자만** 보낸다("어제 채널별 매출·마진 요약 코멘트"). 원시 주문행은 보내지 않는다.
4. 서버·DB는 **국내 리전**(NCP·KT Cloud·AWS 서울 리전 등)에 둔다. 해외 사업자의 서울 리전도 위탁이지만, 국외이전 논점은 크게 줄어든다.
5. 그래도 해외 업체(LLM API, 구글 시트, n8n Cloud 등)를 쓰면 위탁계약 부속서에 **재수탁자 목록(업체, 국가, 항목, 목적, 보관 기간)**을 넣고 셀러의 서면 동의를 받는다. 셀러 처리방침용 공개 문구도 제공한다.
6. B는 **고객사 명의의 API 키·클라우드 계정을 쓰는 것을 기본값**으로 한다(고객사가 처리자이자 계약 당사자가 되므로 창업자의 재위탁 문제가 줄어든다). 운영 DB에 직접 붙지 않고 **마스킹된 스테이징 데이터**로 개발한다.

**네이버 구간의 실행 가능한 대안 (위험 낮은 순)**
1. **법인 설립 후 API대행사 신청**: 1인 법인 설립 비용은 수십만원대 **(추정, 법무사 견적 필요)**. 리테이너 고객이 3곳 이상 확인되는 시점(실험 Go 이후)에 검토한다. 신청 전에 네이버 기술지원 메일로 "1인 법인, 맞춤 자동화 대행" 형태가 승인 대상인지 먼저 묻는다.
2. **이미 승인된 통합관리 솔루션 위에 얹기**: 셀러가 쓰는 사방넷·플레이오토·이지어드민 등의 엑셀 내보내기나 그 솔루션이 제공하는 API로 데이터를 받는다. 네이버 키를 직접 다루지 않는다. 각 솔루션의 API 약관은 별도로 확인한다.
3. **"구축 후 인계(셀러 자가 운영)"형**: 셀러 명의의 서버·계정에 셀러가 직접 만든 애플리케이션으로 자동화를 설치하고 운영권을 넘긴다. 창업자는 키를 보관하지 않는다. 다만 이후 유지보수 때 셀러 계정에 접속해 운영하면 네이버 문구상 "위탁받아 운영"에 해당할 수 있어 **회색지대**다. 월 운영 리테이너와는 구조적으로 맞지 않는다.
4. **크몽 29만원 단건(실험 A)**: 2번(인계형)으로만 납품한다. 네이버 키를 창업자 서버에 상시 보관하는 상품은 법인·대행사 등록 전까지 팔지 않는다.

"거래 완료 후 일정 기간 직거래 금지" 같은 기간 조항이 있는지 직접 확인해야 한다.** 크몽에는 "월 구독형 유지관리" 형태의 상품도 존재한다(초기 세팅비 + 월 구독). 출처: [크몽 판매 이용약관 개정 안내(2026-02-05)](https://support.kmong.com/hc/ko/articles/54644452688793-%ED%8C%90%EB%A7%A4-%EC%9D%B4%EC%9A%A9%EC%95%BD%EA%B4%80-%EA%B0%9C%EC%A0%95-%EC%95%88%EB%82%B4-2026-02-05), [크몽 월구독형 운영 서비스 예시](https://kmong.com/gig/786699)

- 대응:
  - 크몽에서 만난 고객의 **월 운영도 크몽 구독형 상품으로** 받는다. 수수료를 감수한다. 크몽 고객을 자체 계약으로 옮기지 않는다.
  - 크몽 메시지·납품물·PDF 리포트·코드 주석에 **개인 연락처, 홈페이지, 카톡 ID를 넣지 않는다**(자동 탐지 대상).
  - 고객이 먼저 "세금계산서 때문에 직접 계약하자"고 해도 크몽 고객센터에 먼저 문의하고, 답변을 기록해 둔다.

### 1-6. 계약 리스크

**(1) 손해배상 한도**
- 민법상 배상 범위는 통상손해가 원칙이고, 특별손해는 예견할 수 있었던 경우에만 인정된다(제393조). 한도 조항이 없으면 셀러의 일실이익·플랫폼 페널티·구매자 배상까지 청구될 수 있다.
- 표준 계약서를 여러 고객에게 똑같이 쓰면 **약관규제법**이 적용될 수 있다. 제7조는 고의·중과실 면책을 무효로 하고, "상당한 이유 없이" 배상 범위를 제한하는 조항도 무효가 될 수 있다. 출처: [약관규제법 제7조](https://casenote.kr/%EB%B2%95%EB%A0%B9/%EC%95%BD%EA%B4%80%EC%9D%98_%EA%B7%9C%EC%A0%9C%EC%97%90_%EA%B4%80%ED%95%9C_%EB%B2%95%EB%A5%A0/%EC%A0%9C7%EC%A1%B0)
- 권장 문구 구조:
  - 총 배상 한도 = **직전 3개월(또는 12개월) 동안 실제로 받은 대금**
  - 간접·특별·결과적 손해(일실이익, 플랫폼 페널티, 영업손실) 제외
  - **단, 고의·중과실, 개인정보 유출, 비밀유지 위반은 한도에서 제외(또는 별도 상향 한도)**: 이렇게 써야 조항 전체가 무효가 될 위험이 줄어든다. 개인정보 유출을 한도에서 빼면 창업자 부담이 커지므로 보험(1-7)과 짝을 맞춘다.
  - 한도의 "상당한 이유"(저가 정액 요금, 고객 측 검수 의무, 보험 범위)를 계약서 전문이나 조항에 적는다.

**(2) 장애·오류 책임 (A: 잘못된 재고 동기화로 과판매 등)**
- 시나리오: 동기화가 멈추거나 수량이 잘못 반영돼 품절 상품이 팔림 → 셀러가 주문을 취소하고 플랫폼의 품절취소·발송지연 페널티, 구매자 불만, 판매지수 하락을 겪는다. 손해가 한 번에 수백만원 단위로 커질 수 있다 **(추정)**.
- 설계로 막기: ① 재고 수량 **안전 버퍼**(예: 실제 재고 −N) ② 이상치 차단(한 번에 ±X% 넘게 바뀌면 반영 보류하고 알림) ③ 동기화 실패 시 **즉시 카톡·슬랙 알림**과 "마지막 성공 시각" 표시 ④ 처음 2주는 **드라이런 모드**(쓰기 없이 비교 리포트만) ⑤ 쓰기 작업은 로그를 남기고 되돌릴 수 있게.
- 계약으로 막기: 서비스 수준은 "합리적 노력(best effort)", 가용성 수치 보장 없음 또는 낮게. 고객의 **최종 확인 의무**(재고·가격·정산은 고객이 최종 책임). 플랫폼 API 장애·사양 변경·레이트 리밋·키 만료(쿠팡 180일)는 면책. 장애 통지·대응 시간(영업시간 기준) 명시. 고객이 알림을 받고도 조치하지 않아 생긴 손해는 제외.

**(3) 코드·IP 귀속**
- 저작권법상 계약이 없으면 저작권은 원칙적으로 **창작자(창업자)**에게 있다. 업무상저작물 규정은 고용 관계에 적용되는 것이 원칙이다 **(전문가 확인 필요)**. 그래서 귀속을 계약으로 분명히 해야 분쟁이 없다.
- 권장안:
  - **A(호스팅·운영형)**: 플랫폼·템플릿·워크플로의 IP는 창업자가 보유하고 고객에게는 이용권을 준다. 고객 데이터와 리포트 결과물은 고객 소유. 해지 시 **데이터 내보내기**(CSV 등)는 보장하고, 워크플로 소스 인계는 별도 유상 옵션으로 둔다.
  - **B(맞춤 개발형)**: 대금을 완납하면 그 고객 전용 결과물의 저작권은 고객에게 양도한다. 단 **사전 보유 IP, 범용 모듈, 템플릿, 노하우**는 창업자가 보유하고 고객에게 영구·무상 이용권을 준다. 이 조항이 없으면 다음 고객에게 템플릿을 재사용할 때 분쟁이 생긴다.
  - 오픈소스 라이선스 준수(GPL 계열 포함 여부 고지). n8n은 "Sustainable Use License"라서 **타인에게 n8n을 호스팅해 주는 상업 서비스에는 제약이 있을 수 있다. n8n 라이선스 원문을 확인해야 한다(A의 "셀프호스팅 n8n으로 여러 고객 운영" 구조에 직접 걸린다).**
  - AI가 생성한 코드는 저작권 보호 범위가 불확실하다는 점을 고지하고, 제3자 권리 침해가 없다는 보증은 "창업자가 아는 범위"로 한정한다.
  - 포트폴리오·익명 사례 사용 허락 조항.

**(4) 하자보수**
- 소프트웨어 개발은 도급으로 보는 것이 판례 경향이다. 수급인의 하자담보책임(민법 제667조 이하)이 적용된다. 출처: [KCI — 프로그램 개발공급계약의 하자](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART001660074)
- 권장: 검수 기간(납품 후 7영업일, 기간이 지나면 검수 완료로 간주), **무상 하자보수 기간**(셋업 납품 후 1~3개월), 하자 정의(합의된 명세와 다르게 동작하는 것. 신규 요구·플랫폼 변경은 제외). 월 운영 계약 중에는 운영비에 하자 대응이 포함된다고 명시한다.

**(5) 범위 관리 (특히 B)**
- "요청 무제한"은 분쟁의 씨앗이다. "1건 = 개발 8시간 이내", 동시 진행 1건, 납기는 요청 확정 후 영업일 기준, 큰 건은 별도 견적, 미사용 분 이월 없음, 월 단위 해지 시 진행 중인 건의 처리 방법을 정한다.

**(6) 세금계산서·부가세 (용역 vs 구독)**
- 셋업(용역 완성)과 월 운영·구독(계속적 용역 공급)은 모두 **과세 용역**이다. 일반과세자는 부가세 10%를 별도로 받고 세금계산서를 발행한다. 월 구독은 대가를 받기로 한 때마다(보통 매월) 발행한다 **(세무사 확인 필요)**. 계약서와 견적서에 **"부가세 별도"**를 명시한다(02-ideas의 가격은 부가세 별도 기준).
- **간이과세자**는 연매출 4,800만원 미만이면 세금계산서를 발행할 수 없다. 4,800만~1억400만원 구간은 발행 가능하다 **(현행 기준은 세무사 확인 필요)**. 월 500만원 목표면 곧 일반과세 전환 구간이다.
- **3.3% vs 사업자**: 창업자는 사업자등록이 있으므로 원칙적으로 **세금계산서 발행 + 부가세 10%**다. 고객사가 습관적으로 3.3%를 원천징수하려 하면 이중 처리가 된다. 3.3% 원천징수는 사업자등록이 없는 인적용역 사업소득자에게 적용하는 방식이고, 세금계산서와 같이 가지 않는다. 출처: [flowworks — 세금계산서 vs 3.3%](https://flowworks.io/blog/freelancer-tax-invoice-handling), [save-tax — 프리랜서 사업자 등록 기준](https://www.save-tax.co.kr/blog/%ED%94%84%EB%A6%AC%EB%9E%9C%EC%84%9C-%EA%B0%9C%EC%9D%B8-%EC%82%AC%EC%97%85%EC%9E%90-%EB%93%B1%EB%A1%9D-%EA%B8%B0%EC%A4%80-3%EA%B0%80%EC%A7%80-ft-%EC%82%AC%EC%97%85%EC%9E%90-%EB%93%B1%EB%A1%9D)
- 크몽 매출은 크몽이 정산하지만 매출 신고 의무는 창업자에게 있다. 업종코드(정보통신업, SW 개발·공급 등)가 현재 사업자등록(앱 개발)과 맞는지 확인하고, 필요하면 업종을 추가한다.
- 해외 LLM·VPS 비용은 해외 결제라 매입세액 공제 대신 경비 처리 위주가 된다 **(세무사 확인 필요)**.

### 1-7. 배상책임보험 (IT 전문인 / 사이버 / 개인정보)

- **의무 여부**: 개인정보 손해배상책임 보장 의무(제39조의7)는 "전년도 매출 10억원 이상 **그리고** 정보주체 1만명 이상(일평균, 직전 3개월)"인 처리자가 대상이다. 정부는 의무 대상을 매출 1,500억원·100만명 이상으로 조정하는 방향을 발표했다. **창업자는 의무 대상이 아니다.** 출처: [디지털투데이 — 보장제 개편](https://www.digitaltoday.co.kr/news/articleView.html?idxno=559025), [IT위키 — 제39조의7](https://itwiki.kr/w/%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4_%EB%B3%B4%ED%98%B8%EB%B2%95_%EC%A0%9C39%EC%A1%B0%EC%9D%987)
- **그래도 필요한가**:
  - **A: 필요(권장 강함).** 여러 셀러의 구매자 개인정보와 API 키를 한 서버에 모은다. 사고 한 번에 고객 전체가 연쇄 피해를 입는 구조다. 재고 오류 같은 업무 과실도 "전문직업(IT E&O)" 배상 영역이다.
  - **B: 권장(중간).** 고객사 시스템 장애나 데이터 손상 위험이 있다. 투자 받은 스타트업은 계약 때 보험 가입 증명을 요구하기도 한다 **(추정)**.
- **상품과 비용**:
  - **개인정보보호배상책임(공제)**: 대한상공회의소 공제는 단체할인으로 보험사 직접 가입 대비 최대 50% 이상 저렴하다. 최저 가입금액은 매출·정보주체 수에 따라 5천만원~10억원이다. 소규모는 **연 수십만원 수준으로 추정**한다(견적 필요). 출처: [대한상의 개인정보보호 배상책임 공제](https://insure.korcham.net/Front/Sub/appl/02.asp), [Chubb 개인정보보호배상책임보험(PDF)](https://www.chubb.com/content/dam/chubb-sites/chubb-com/kr-kr/factsheets/personal-information-protection-compensation-liability-insurance_2_202406.pdf)
  - **IT 전문직업배상(E&O)·사이버배상**: 국내 손보사에 "컴퓨터·소프트웨어 개발업" 전문직업배상 상품이 있다. 보험료는 보상한도(1억 vs 10억)에 따라 크게 달라진다. 중소기업 사이버보험은 연 수백만원 수준이라는 자료가 있지만, 1인·소매출 사업자는 이보다 낮을 것으로 **추정**한다(견적 필요). 출처: [smallake — 소프트웨어 손해배상](https://smallake.kr/?p=1895), [Gain Lab — 사이버배상책임보험](https://gainlab.co.kr/36), [한국화재보험협회 — 국내 사이버보험 현황](https://www.kfpa.or.kr/webzine/202402/disaster3.html)
  - 소프트웨어공제조합(SW공제조합) 조합원 보증·공제 상품도 비교 대상이다. 출자금이 필요하다 **(확인 필요)**.
- **권장 순서**: 첫 유료 A 고객의 데이터를 받기 **전에** 개인정보보호배상(최소 한도)에 가입한다. 월 매출 300만원을 넘거나 B 고객이 요구하면 E&O를 추가한다. 보험 약관에서 **"계약상 가중된 책임" 면책 조항**을 확인하고, 계약서 배상 한도를 보험 한도 안으로 맞춘다.

### 1-8. AI 기본법이 대행업자에게 미치는 영향

- 시행: **2026-01-22**. 과태료(최대 3,000만원)는 **최소 1년 계도기간**(사실조사·과태료 유예)이 있어 2027-01-22 이전에는 사실상 부과되지 않는다. 정부는 연장 가능성도 열어 뒀다. 출처: [AI타임스 — 1년간 규제 유예](https://www.aitimes.com/news/articleView.html?idxno=205781), [파이낸셜뉴스](https://www.fnnews.com/news/202512310902359712), [전자신문 — 시행령 입법예고](https://www.etnews.com/20251112000177)
- 수범자: "인공지능사업자" = 개발사업자 + **이용사업자(남의 AI를 이용해 AI 제품·서비스를 제공하는 자)**. AI를 업무 도구로만 쓰는 사람은 "이용자"라서 의무가 없다. 외부 AI를 갖다 써서 AI 기반 서비스를 **납품·제공**하면 이용사업자로 볼 수 있다는 해설이 있다. 출처: [헬프미 — AI 기본법 3가지 의무](https://www.help-me.kr/blog/article/korea-ai-act-2026-compliance-guide/), [법률신문 — "AI 썼을 뿐인데 인공지능사업자?"](https://www.lawtimes.co.kr/news/articleView.html?idxno=215586), [세종 — AI 기본법 시행과 시사점](https://www.shinkim.com/kor/media/newsletter/3114)
- **A: 영향 낮음.** 결과물은 셀러 내부용 리포트·알림이다. 생성형 AI 결과물을 일반 이용자에게 "제공"하는 서비스가 아니다. 고영향 분야(의료·채용·신용 등)도 아니다. 그래도 리포트의 AI 코멘트에 "AI 생성 요약" 표기를 넣는 것은 비용이 거의 들지 않고 좋은 관행이다.
- **B: 영향 낮음~중간.**
  - 내부툴·업무 자동화: 낮음.
  - 고객사의 **최종 사용자에게 노출되는 생성형 AI 기능**(챗봇, AI 생성 콘텐츠): 그 서비스를 제공하는 **고객사**가 사전 고지·생성물 표시 의무의 1차 주체다. 다만 개발·납품한 창업자도 이용사업자로 엮일 수 있다는 해석이 있다. 계약서에 "AI 고지·표시 의무 이행 주체는 서비스 운영자(고객사)"로 정하고, **표시 기능은 기본값으로 구현해 넘긴다**.
  - **채용 서류 평가, 신용·대출 판단, 의료 판단 같은 고영향 AI**는 영향평가·설명 의무가 붙는다. 1인 구독 상품 범위에서 **수주하지 않는다**.
- EU AI Act: 해외 고객이 없으면 해당 없음.

### A 최종 판정: **조건부 진행**
- **원안(셀러 API 키를 받아 창업자 서버에서 상시 운영 + 월 리테이너) 중 네이버 구간은 "재검토 필요"**다. 이 구조는 네이버가 공식 답변으로 금지했고, 합법 경로(API대행사)는 법인 요건 때문에 지금 막혀 있다.
- 진행 조건:
  1. 네이버 데이터는 ① 셀러 자가 운영 인계형 ② 승인된 통합관리 솔루션 경유 ③ 법인 설립 + API대행사 등록 중 하나로만 처리한다. 2주 실험(크몽 29만원 단건)은 ①로 납품한다.
  2. 첫 고객 데이터를 받기 전에 위탁계약서, PII 제거 설계, MFA·접속기록·국내 리전, 개인정보보호배상 공제를 갖춘다.
  3. 재고 쓰기 기능은 드라이런 2주와 안전 버퍼 뒤에 켜고, 계약서 책임 한도와 고객 확인 의무를 넣는다.
  4. 실험 A가 Go(셋업 선금 + 운영비 수락)면 **법인 전환 비용과 일정**을 다음 단계 사업계획에 넣는다. 법인 전환을 원하지 않으면 A는 "쿠팡·자사몰 중심 + 네이버는 인계형"으로 상품을 다시 정의한다.

### B 최종 판정: **조건부 진행**
- 구조적으로 막히는 규제는 없다. 리스크 대부분은 **계약서와 작업 습관**으로 통제할 수 있다.
- 진행 조건:
  1. 표준 계약서(구독 약관 + NDA + 개인정보 위탁 부속서 + AI 도구 사용 동의)를 첫 데모 전에 준비하고 변호사 검토를 1회 받는다.
  2. 운영 DB·실데이터를 LLM에 넣지 않는 작업 규칙(마스킹 스테이징, 고객 명의 키)을 지킨다.
  3. 채용·신용·의료 판단 같은 고영향 AI와 대량 개인정보 처리 프로젝트는 구독 범위에서 뺀다.
  4. 월 선결제와 미납 시 중지 조항을 둔다.

## 4. 계약서에 꼭 넣을 조항 체크리스트

공통(A·B)
- [ ] 당사자, 서비스 범위(**포함/제외 목록**), 산출물 정의
- [ ] 요금: **부가세 별도**, 세금계산서 발행, **월 선결제**, 연체 시 서비스·호스팅 중지 권리, 가격 조정 규정
- [ ] 계약 기간, 자동 갱신, 해지 통지 기간(예: 30일), 해지 시 진행 중인 건과 데이터 반환·파기 절차
- [ ] 검수 기간(7영업일, 지나면 검수 완료 간주)과 **무상 하자보수 기간**(1~3개월), 하자 정의(명세 불일치에 한정, 신규 요구·플랫폼 변경 제외)
- [ ] **손해배상 한도**: 직전 3개월(또는 12개월) 실수령 대금. **간접·특별·결과적 손해(일실이익, 플랫폼 페널티) 제외**. 단 고의·중과실은 예외임을 명시(약관규제법 대응). 개인정보 유출은 별도 한도(보험 한도와 맞춤)
- [ ] 면책: 제3자 플랫폼·API 장애, 사양 변경, 레이트 리밋, 키 만료·권한 회수, 고객 측 입력 오류, 고객이 알림을 받고도 조치하지 않은 경우
- [ ] **고객의 최종 확인 의무**: 재고·가격·정산·외부 발송 내용은 고객이 최종 확인하고 책임진다
- [ ] 서비스 수준: 합리적 노력, 장애 접수 채널과 대응 시간(영업시간 기준), 가용성 수치 미보장 또는 낮은 수치
- [ ] **지식재산권**: (A) 플랫폼·템플릿은 창업자 보유, 고객 데이터·리포트는 고객 소유, 해지 시 데이터 내보내기 보장 / (B) 완납 시 전용 결과물 양도 + **사전 보유 IP·범용 모듈은 창업자 보유, 고객에 영구 이용권**
- [ ] 오픈소스 사용 고지, AI 생성물 저작권 불확실성 고지, 제3자 권리 비침해 보증은 "알고 있는 범위"로 한정
- [ ] **AI 도구 사용 동의**: 사용하는 LLM·도구 이름, 처리 국가, 데이터 보관·학습 미사용 정책, 개인정보·비밀정보 입력 금지 원칙
- [ ] 비밀유지(상호, 계약 종료 후 2~3년), 좁은 범위의 경업 제한만 수용
- [ ] 금지 업무: 위탁 목적 외 개인정보 이용(구매자 대상 마케팅 등), 법령·플랫폼 약관 위반 요청, 고영향 AI
- [ ] 포트폴리오·익명 사례 사용 허락
- [ ] 분쟁 해결: 협의 → 관할 법원(창업자 주소지)
- [ ] 보험 가입 사실과 한도(가입한 경우)

개인정보 처리위탁 부속서(A 필수, B는 개인정보를 다루면 필수)
- [ ] 위탁 업무의 목적과 범위, 처리 항목(이름·주소 등을 **처리하지 않는다면 그렇게 명시**)
- [ ] 목적 외 처리 금지
- [ ] 기술적·관리적 보호조치(MFA, 암호화, 접근통제, 접속기록 보관·점검, 국내 리전)
- [ ] **재위탁 제한과 재수탁자 목록**(업체·국가·항목·목적·보관 기간). 변경 시 사전 통지와 동의
- [ ] 국외이전 사항(해당 시)과 위탁자 처리방침 공개 협조
- [ ] 위탁자의 관리·감독 권한(점검, 자료 요청), 수탁자 교육
- [ ] **유출 인지 시 24시간 안에 위탁자에게 통지**, 협조 의무(72시간 신고 지원)
- [ ] 보관 기간과 파기(종료 시 파기 확인서)
- [ ] 위반 시 손해배상 책임

A 전용
- [ ] 키 발급·소유자 = 셀러, 창업자 = 셀러의 개발·운영 위탁업체. 각 플랫폼 약관 준수 책임 분담
- [ ] 네이버 구간 처리 방식(인계형/솔루션 경유/대행사) 명시
- [ ] 재고 동기화: 안전 버퍼 값, 드라이런 기간, 이상치 차단 규칙을 **고객이 승인**했다는 기록
- [ ] 플랫폼 페널티·구매자 배상은 간접손해로 제외

B 전용
- [ ] "1건" 정의(개발 8시간 이내), 동시 진행 1건, 납기 기준(요청 확정 후 영업일), 큰 건 별도 견적, 미사용 이월 없음
- [ ] 고객 계정·권한 발급 방식(개인 계정, 최소 권한), 종료 시 권한 회수
- [ ] 운영 배포 전 고객 검수, 운영 데이터 직접 접근 제한
- [ ] AI 기능 납품 시 고지·표시 의무 이행 주체 = 고객사

## 5. 지금 당장 할 일 (우선순위)

1. **네이버 기술지원에 문의**(이번 주): "개인사업자(또는 1인 법인)가 셀러 위탁으로 정산·재고 자동화를 운영하는 경우의 합법 경로"를 묻고 답변을 저장한다. 실험 A의 크몽 상품 설명에는 "셀러 계정에 설치·인계"라고 적는다.
2. **계약서 템플릿 3종**(구독·용역 약관, 개인정보 위탁 부속서, NDA): 과기정통부 SW 표준계약서 등을 참고해 초안을 만들고 변호사 검토 1회(비용 수십만원대, **추정**).
3. **데이터 설계 원칙 문서화**: PII 즉시 제거, HMAC 가명 ID, LLM에는 집계만, 국내 리전, 키 비밀 저장소.
4. **개인정보보호배상 공제 견적**(대한상의) → A 첫 고객 전에 가입.
5. **n8n 라이선스와 쿠팡 Open API 약관 원문 확인**(차단 없는 환경에서).
6. **세무사 1회 상담**: 업종코드 추가, 간이/일반 과세 전환 시점, 월 구독 세금계산서 발행 시기, 법인 전환 손익.
7. 영업은 1-4 표의 "안전" 채널만 쓴다. "공개 제휴 창구 1:1"은 쓰더라도 10건 이내로 제한하고, (광고) 표기와 수신거부 방법을 넣는다.
