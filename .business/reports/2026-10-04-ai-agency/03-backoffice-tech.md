## 0. 판정: 조건부 가능

**기술적으로는 쉽다. 막히는 지점은 채널 정책(특히 네이버), 라이선스, 운영 규율이다.** 법인을 세우기 전후로 구조가 달라진다.

| 구분 | 판정 | 이유 |
|---|---|---|
| 쿠팡 | 가능(위험 낮음) | 셀러가 "자체개발(직접입력)" 칸에 창업자 서버 IP를 등록하는 방식이 업계 관행이고, 연동 업체들이 공식 안내한다. **단, 쿠팡 약관 원문으로는 확인하지 못했다** |
| 카페24·아임웹·11번가 | 가능 | 카페24는 제3자 앱(OAuth) 구조다. 아임웹·11번가는 셀러가 발급한 키로 셀러툴들이 연동하는 것이 일반적이다 |
| **네이버 스마트스토어 직접 API(대행사 서버에서 운영)** | **법인 전에는 불가** | 네이버 공식 답변(GitHub Discussion #3463, 2026-04-28)은 판매자의 "내스토어 애플리케이션" 정보를 넘겨받아 대행사가 대신 운영하는 것을 금지한다. 허용 경로는 커머스솔루션 등록과 API대행사 등록 두 가지다. API대행사는 **국내 법인이 아니면 반려될 수 있고**, 창업자는 개인사업자다 |
| 네이버를 법인 전에 다루는 방법 | 조건부 가능 | 대안 3가지 중 하나를 고른다(1-4절). **기본은 (2) 승인된 통합솔루션 경유.** (1) 인계형은 예외로만 쓰고, (3) 1인 법인 설립 후 API대행사 신청을 3~6개월 차 목표로 둔다 |
| G마켓·옥션(ESM), 카카오 선물하기 | 조건부 | 둘 다 셀링툴 업체나 연동대행사로 등록하고 승인을 받아야 하며, 승인은 플랫폼 재량이다. 법인 전에는 통합솔루션을 거치는 편이 현실적이다 |
| 재고 "양방향" 동기화(채널에 재고 수량 쓰기) | 초기에는 비추천 | 버그 하나가 오버셀(재고 없는 상품 판매)로 이어지고 그 손해는 대행사 책임이 된다. 통합솔루션이 이미 하는 기능이다 |
| 주문 취합·정산 대사·손익 리포트(읽기 전용) | 가능 | 핵심 가치이면서 위험이 낮다 |
| "창업자 서버 호스팅으로 락인" 설계를 n8n으로 구현 | 불가(라이선스) | n8n Sustainable Use License상 창업자 서버 한 대에 여러 고객의 워크플로와 자격증명을 올려 호스팅하면 상용 라이선스가 필요하다. 직접 작성한 코드나 MIT 라이선스인 Activepieces로 구현한다 |
| 1인이 15곳 운영 | 조건부 | 중앙 멀티테넌트 구조 + 표준 커넥터 + 모니터링 + 키 만료 자동 알림이 갖춰져야 한다. 인계형 고객이 섞이면 상한이 내려간다(5-2절) |

**성립 조건 6가지**
1. **네이버 직접 API를 대행사 서버에서 돌리지 않는다.** 법인 전에는 이미 승인된 통합솔루션(사방넷·플레이오토·이지어드민 등)의 API·내보내기를 거치거나, 셀러가 스마트스토어센터에서 엑셀을 내려받아 올리게 한다. 인계형은 셀러가 원할 때만 쓴다. **스크래핑과 고객 ID·비밀번호 위임 로그인은 하지 않는다.**
2. **3~6개월 차에 1인 법인을 세우고 네이버 API대행사를 신청한다.** 그 전까지 네이버는 "반자동"이 될 수 있다는 점을 영업 단계에서 밝힌다.
3. **상품 범위는 "읽기 전용 + 알림"으로 시작한다.**
4. **운영 엔진은 직접 작성한 코드로 만든다.** 창업자 서버에서 n8n을 여러 고객용으로 돌리지 않는다.
5. **서버는 국내 리전에 고정 IP로 둔다.** IP 화이트리스트(쿠팡·네이버·11번가)를 맞추고, 주문자 개인정보의 국외이전도 피할 수 있다.
6. **주문 데이터를 받는 즉시 이름·전화·주소를 지운다.** 구매자를 구분해야 하면 HMAC 가명 ID만 쓰고, LLM에는 집계값만 보낸다.

### 1-2. 스크래핑은 하지 않는다

- 판매자센터를 크롤링하려면 고객의 ID·비밀번호와 2단계 인증을 넘겨받아야 한다. 그러면 세 가지 문제가 생긴다. ① 플랫폼 약관의 계정 공유·자동 접속 금지에 걸린다. ② 계정이 정지되면 **고객 매출이 멈추고** 그 책임이 대행사로 온다. ③ 화면이 바뀔 때마다 깨진다.
- API로 받을 수 없는 정산 데이터는 반자동으로 처리한다. **고객이 엑셀을 공유 드라이브에 올리면 자동으로 파싱**한다. 셀러가 자기 판매자센터에서 직접 내려받는 것이라 정책 문제가 없다.

### 1-3. 통합솔루션 위에 얹는 방식 (사방넷·플레이오토·이지어드민)

| 솔루션 | API 조건(검색 기준) | 얻는 것 | 못 얻는 것 |
|---|---|---|---|
| 사방넷 | API 서비스 실버 **월 10만원**, API 2.0 스탠다드 월 27만원 / 프리미엄 월 48만원(본 요금제와 별도) | 수십 개 채널의 주문 수집·재고·송장·문의를 **커넥터 하나로** 받는다. 네이버·ESM·카카오와의 승인 문제는 솔루션사가 이미 해결해 둔 상태다 | 채널별 **수수료와 정산 금액**은 기본적으로 들어오지 않는다고 봐야 한다(확인 필요) |
| 플레이오토 2.0 | BASIC 요금제 이상 + API연동 부가서비스 구매 + 개발자센터 신청(승인 2~5일) | 상품, 주문, 재고 API | 정산 |
| 이지어드민 등 | API 조건 미확인. 최소한 주문·재고 엑셀 내보내기는 가능 | 내보내기 파일 자동 파싱 | 정산 |

**결론: 법인 전에는 이것이 네이버를 포함한 다채널 주문 데이터의 기본 경로다.**
- 타깃 고객(월매출 5천만~5억원, 다채널)은 이미 통합솔루션을 쓰고 있을 가능성이 높다. 이들의 불만은 "주문은 모였는데 **손익과 정산 대사는 여전히 엑셀**"이라는 것이고, 이 사업의 가치 제안과 정확히 겹친다.
- 구성: **주문·재고는 통합솔루션 API나 내보내기로, 정산은 쿠팡 API + 네이버·기타 채널 엑셀 업로드로 받는다.**
- 단점: API를 쓰면 고객이 월 10만원 이상을 추가로 낸다. 내보내기 파일을 쓰면 추가 비용은 없지만 반자동이 된다.
- **타깃 조정**: 법인 전 첫 고객은 "통합솔루션을 이미 쓰는 셀러" 또는 "쿠팡 비중이 큰 셀러"를 우선한다. 네이버 단일 채널 셀러는 법인 전에는 가치가 약하다.

### 1-4. 네이버: 법인 전후 경로 비교

| 경로 | 시점 | 비용·시간 | 자동화 수준 | 위험 | 채택 |
|---|---|---|---|---|---|
| X. 고객의 내스토어 앱 키를 받아 대행사 서버에서 호출 | - | 0원 | 완전 자동 | **네이버 정책 위반**(공식 답변으로 명시). 적발되면 앱 휴면과 고객 신뢰 상실 | **불가** |
| (2) 승인된 통합솔루션의 API·내보내기 경유 + 정산 엑셀 업로드 | 법인 전 기본 | 고객이 월 0~10만원 이상 부담 | 주문은 자동 또는 반자동, 정산은 반자동(고객이 주 1회 2분 작업) | 솔루션사 정책에 종속. 고객이 업로드를 잊을 수 있다 → 리마인드 알림 | **기본** |
| (1) 인계형: 창업자가 구축하고, 셀러가 **자기 서버·계정**에서 자기 내스토어 앱으로 직접 운영 | 법인 전 예외 | 셀러가 VPS 월 1.5만원 안팎 부담, 고객마다 별도 배포 | 완전 자동 | ① 정책상 "셀러가 직접 연동"에 해당하려면 **키와 서버 통제권이 셀러에게 있어야 한다.** 창업자가 셀러 서버에 상시 접속해 운영하면 다시 "위탁 운영"으로 볼 여지가 있다(회색지대, 네이버 확인 필요) ② 월 운영 리테이너와 락인이 약해진다 ③ 고객마다 서버가 따로 있어 1인 운영 부담이 커진다 | **셀러가 원할 때만, 구축비 중심 상품으로** |
| (3) 1인 법인 설립 → API대행사 신청 | 3~6개월 차 | 법인 설립 실비 수십만원(셀프 등기 기준 추정) + 심사 기간 | 완전 자동. 셀러는 스마트스토어센터에서 대행사 지정만 하면 된다 | 신규·소규모 법인은 "실제 서비스로 판단하기 어렵다"는 이유로 반려될 수 있다. 고객 3~5곳 레퍼런스를 만든 뒤 신청한다 | **중기 목표** |

**인계형(1)을 쓸 때의 운영 원칙** (회색지대를 줄이기 위해)
- 서버와 클라우드 계정은 셀러 명의, 결제도 셀러 카드로 한다. 네이버 앱도 셀러가 직접 등록하고 키를 셀러가 입력한다.
- 창업자는 구축과 정기 업데이트 배포만 맡는다. 접속은 셀러가 그때그때 허용하는 임시 권한으로 하고 상시 관리자 권한은 받지 않는다.
- 월 운영비는 "호스팅·운영 대행"이 아니라 **"소프트웨어 업데이트·기술지원"**으로 계약한다.
- 이 구조라면 셀러 소유 서버에 n8n을 설치하는 것도 라이선스상 허용된다(고객 소유 인스턴스).
- 법인을 세운 뒤 API대행사 승인이 나면 중앙 멀티테넌트로 옮긴다.

## 3. AI가 들어가는 지점과 비용

**솔직한 평가: 이 사업의 본체는 결정론적 데이터 파이프라인(ETL + 규칙)이고 LLM은 보조다.** 가장 큰 AI 레버리지는 고객 납품 기능이 아니라 **창업자가 Claude Code로 커넥터와 테스트를 빠르게 만드는 개발 생산성**이다. 정산 숫자 자체는 절대 LLM이 계산하지 않게 설계한다(환각 차단).

### 3-1. 개인정보 처리 설계 (규제 검토 권고 반영)

1. **수집 즉시 삭제**: 커넥터가 응답을 받으면 DB에 쓰기 전에 주문자·수령인의 이름, 전화번호, 주소, 개인통관고유부호, 배송메모를 지운다. **원본 JSON 보관(raw_events)도 삭제한 뒤의 상태로만 저장한다.** 손익·정산 분석에는 이 필드가 필요 없다.
2. **구매자 구분이 필요할 때(재구매율, 동일인 중복 주문 탐지 등)**: `buyer_pid = HMAC-SHA256(테넌트별 비밀키, 정규화한 전화번호 또는 채널 회원 ID)`만 저장한다. 키 없이는 원래 값을 복원할 수 없고, 테넌트별로 키가 달라서 고객 간 데이터를 연결할 수 없다. 키를 폐기하면 가명 ID도 사실상 익명화된다.
3. **주문번호**: 정산 대사에는 주문번호가 필요하다. 주문번호는 개인 식별 정보는 아니지만, 리포트와 LLM 입력에서는 가명 토큰으로 바꾸고 원래 값은 서버 안에서만 쓴다.
4. **LLM에는 집계값만 보낸다**: 개인정보를 LLM API로 보내면 재위탁·국외이전(개인정보 보호법 제28조의8)에 해당할 수 있다. 모든 LLM 호출은 `llm/` 게이트웨이 한 곳에서만 나가게 하고, 허용 필드 화이트리스트와 정규식 PII 검사(전화번호·주소 패턴)를 통과한 데이터만 전송한다. 차단되면 로그를 남기고 호출을 중단한다.
5. **서버는 국내 리전에 둔다.** Sentry 같은 해외 SaaS 모니터링에는 PII 스크러빙을 켜고 요청 본문을 보내지 않는다.
6. **계약**: 셀러와 개인정보 처리위탁 계약을 맺는다(셀러의 개인정보처리방침에 수탁자로 기재). "수집 즉시 개인정보 삭제, 가명 ID만 보관, LLM에는 통계만 사용"을 명시한다.

### 3-2. 기능별 비용

모델 가격(2026-10 공식): Claude Haiku 4.5는 입력 $1 / 출력 $5 per MTok(배치 $0.5/$2.5), Claude Sonnet 5.5는 입력 $2 / 출력 $10(배치 $1/$5)이다. Claude 4.7 이후 모델은 같은 텍스트에서 토큰이 약 30% 더 나오므로 1.3배 버퍼를 둔다.

| # | 지점 | 방식 | LLM에 가는 데이터 | 고객 1곳 월 사용량 가정 | 계산식 | 월 비용 |
|---|---|---|---|---|---|---|
| 1 | 상품명·옵션 매칭(채널 상품 ↔ 내부 SKU) | 문자열 정규화로 후보를 추린 뒤 Haiku가 매칭 여부와 신뢰도를 판정하고 사람이 승인한다. **셋업 시간을 가장 많이 줄인다** | 상품명·옵션명만(개인정보 아님) | 셋업 1회 500개, 이후 신규 월 50개. 건당 입력 300·출력 100토큰(배치) | 셋업: 500×(300×0.5+100×2.5)/1M = $0.20(1회). 월: 50건 → $0.02 | $0.02 |

## 7. 2주 실험(실험 A)에 반영할 수정사항

1. **데모는 "쿠팡 API + 스마트스토어 정산 엑셀 업로드"로 만든다.** 네이버 내스토어 키를 받아 대행사 서버에서 데모하는 방식은 정책 위반이다.
2. **데모부터 직접 작성한 코드(Python)로 만들고, PII 삭제·HMAC 가명화 계층을 처음부터 넣는다.** 나중에 넣으면 이미 쌓인 데이터를 정리해야 한다.
3. 진단 콜에서 반드시 물어볼 것: ① 통합솔루션을 쓰는지, 어떤 요금제인지 ② 채널별 매출 비중(쿠팡 비중이 크면 바로 완전 자동이 가능) ③ 원가표가 있는지 ④ 네이버를 완전 자동으로 원하면 인계형(셀러 서버) 의향이 있는지.
4. 영업 문구에서 "네이버는 법인 대행사 등록 전까지 주 1회 엑셀 업로드(2분)"를 숨기지 않는다.
5. 크몽 29만원 라이트 상품은 **창업자 서버에서 돌아가는 1개월 체험 후 월 운영으로 전환**하는 구조로 만든다(크몽 정책 범위 안에서, 쿠팡·카페24 등 중앙형 채널 중심).
6. 1일차에 서울 리전 VPS와 고정 IP를 잡고, 쿠팡 테스트 키로 IP 등록 흐름까지 검증한다.
7. **유료 고객 3곳을 확보하면 1인 법인을 세우고 네이버 API대행사를 신청한다.** 쿠팡 약관 원문도 이 시점에 확인한다.
