## 0. 판정: 조건부 가능

**기술적으로는 쉽다. 막히는 지점은 채널 정책, 라이선스, 운영 규율이다.**

| 구분 | 판정 | 이유 |
|---|---|---|
| 쿠팡·카페24·아임웹·11번가 연동 | 가능 | 판매자가 키를 발급하고 대행사 서버 IP를 등록하면 끝난다. 쿠팡은 "자체개발(직접입력)" 칸에 대행사 IP를 넣는 방식을 공식 안내한다 |
| **네이버 스마트스토어 직접 API** | **현재 사업자 형태로는 어려움** | 네이버는 외부 업체가 판매자의 "내스토어 애플리케이션" 키를 받아 서비스를 운영하는 것을 금지한다. 정식 경로인 "API대행사"는 **국내 법인 사업자**가 아니면 반려될 수 있다(2026-04 공식 답변). 창업자는 개인사업자다 |
| G마켓·옥션(ESM), 카카오 선물하기 | 조건부 | 둘 다 셀링툴 업체나 연동대행사로 등록하고 승인을 받아야 한다. 승인은 플랫폼 재량이다 |
| 재고 "양방향" 동기화(채널에 재고 수량 쓰기) | 초기에는 비추천 | 기술적으로는 된다. 하지만 버그 하나가 오버셀(재고 없는 상품 판매)로 이어지고 그 손해는 대행사 책임이 된다. 사방넷·플레이오토가 이미 하는 기능이기도 하다 |
| 주문 취합·정산 대사·손익 리포트(읽기 전용) | 가능 | 핵심 가치이면서 위험이 낮다 |
| **"창업자 서버 호스팅으로 락인" 설계를 n8n으로 구현** | **불가(라이선스)** | n8n Sustainable Use License상, 창업자 서버 한 대에 여러 고객의 워크플로와 자격증명을 올려 호스팅하면 상용 라이선스가 필요하다. 직접 작성한 코드나 MIT 라이선스인 Activepieces로 구현해야 한다 |
| 1인이 15곳 운영 | 조건부 | 표준화된 커넥터, 모니터링, 키 만료 자동 알림이 갖춰져야 한다. 없으면 상한은 8~10곳이다 |

**성립 조건 5가지**
1. **네이버는 세 경로 중 하나로 우회한다.** (a) 법인을 세운 뒤 API대행사를 신청한다(심사 반려 가능). (b) 고객이 이미 쓰는 사방넷·플레이오토 API를 거쳐 주문을 받는다. (c) 정산 데이터는 고객이 스마트스토어센터에서 엑셀로 내려받아 공유 폴더에 올린다(반자동). **스크래핑이나 고객 ID·비밀번호를 위임받아 로그인하는 방식은 쓰지 않는다.**
2. **상품 범위는 "읽기 전용 + 알림"으로 시작한다.** 채널에 재고를 쓰는 기능은 기존 통합솔루션에 맡긴다.
3. **멀티테넌트 운영 엔진은 직접 작성한 코드로 만든다.** n8n을 창업자 서버에서 여러 고객용으로 돌리지 않는다. 노코드 도구가 꼭 필요하면 MIT 라이선스인 Activepieces를 쓰거나, 고객 소유의 n8n을 쓴다.
4. **호스팅은 한국 리전에 고정 IP로 둔다.** 쿠팡·네이버·11번가가 모두 IP 화이트리스트를 요구하므로 나가는 IP가 고정되지 않는 서버리스나 GitHub Actions는 쓸 수 없다. 주문자 개인정보를 국외로 옮기는 문제도 함께 피할 수 있다.
5. **주문자 개인정보는 최소한만 수집하고, LLM에는 가명처리하거나 집계한 데이터만 보낸다.** 개인정보를 LLM API로 보내면 재위탁과 국외이전에 해당할 수 있다.

## 1. 채널별 연동 가능성

### 1-1. 요약표

| 채널 | 공식 API | 인증 방식 | 판매자 쪽 절차 | 대행사(제3자)가 운영해도 되나 | 제약 | 정산 데이터 |
|---|---|---|---|---|---|---|
| **네이버 스마트스토어** (커머스API) | 있음 | Client ID/Secret으로 전자서명 후 OAuth2 토큰 발급 | 커머스API센터에서 애플리케이션 등록, 호출 IP 최대 3개 | **내스토어 앱 키를 받아 운영하는 것은 금지.** 허용 경로는 "커머스솔루션"(솔루션마켓 등록)과 "API대행사"(스마트스토어센터에서 대행사 지정) 두 가지이고, API대행사는 **국내 법인 사업자** 요건이 있다 | API마다 초당 호출 허용량이 다르고 넘으면 429(GW.RATE_LIMIT). 애플리케이션 인증 기한이 지나면 자동 휴면 | 정산 API 있음(일별 정산, 건별 정산). 건별 조회는 기간을 하루 단위로만 지정할 수 있고 혜택정산 금액이 0으로 나온다 |
| **쿠팡** (Wing Open API) | 있음 | Access Key/Secret Key HMAC 서명, 업체코드(vendorId) | WING에서 사업자 인증 후 키 발급(발급은 즉시, 권한 반영은 최대 24시간). "연동업체 선택"(1개) 또는 "자체개발(직접입력)"에 IP 최대 10개 | **가능.** 자체개발 칸에 대행사 IP를 입력하는 방식을 연동 업체들이 공식 안내한다 | vendorId당 초당 5회를 넘으면 429. **키는 180일마다 만료되어 재발급해야 한다.** IP·연동업체 목록은 한 달에 10회까지만 수정할 수 있다 | 정산 API 있음(매출내역 조회 `revenue-history` 등) |
| **11번가** | 있음(셀러 API) | 헤더 `openapikey` | 오픈API센터 서비스 등록, Seller API 정보에 IP 등록 | 가능(셀러툴들이 판매자 키를 받아 쓰는 방식이 일반적) | XML 기반 구형 API | **정산 조회 API는 확인하지 못했다.** 셀러오피스 엑셀로 받는다고 가정 |
| **G마켓·옥션** (ESM Trading API) | 있음 | ESM+ 마스터 ID 기반 | ESM+에서 셀링툴 "사용함" 설정 후 셀링툴 업체 지정(상품·주문 각각 최대 5개) | **조건부.** 대행사가 셀링툴 업체로 등록돼야 하고, 업체 사업자 정보로 G마켓·옥션 판매자 회원 가입이 필수다. 승인은 "내부 지원 리소스 범위 안에서"만 나며 반려될 수 있다 | 승인 재량. 문의는 etapihelp@gmail.com | API 범위 확인 필요(엑셀 백업 경로를 확보해 둔다) |
| **카카오 선물하기** (카카오쇼핑 API) | 있음 | 마스터 계정으로 인증키 생성 후 승인 | 별도 접근 권한 신청 → 승인 | **조건부.** "연동대행사" 권한을 받고, 대행사-판매자 연결 API로 매핑해야 한다 | 승인 재량. 사방넷 등은 이미 연동돼 있다 | 확인 못 함 → 엑셀 |
| **카페24** | 있음(REST, 품질 좋음) | OAuth 2.0(앱 등록, Redirect URI) | 개발자센터에서 앱 등록, 판매자가 앱 설치·권한 동의 | 가능(앱 방식 자체가 제3자 연동용) | Leaky Bucket 방식(버킷이 1초에 2회씩 비워짐), 사용량 헤더 제공. 여러 쇼핑몰이 쓰는 비공개 앱에 앱스토어 심사가 필요한지는 **확인 필요** | 주문·결제 데이터로 계산(PG 정산은 별도) |
| **아임웹** | 있음(REST v2) | API Key/Secret으로 액세스 토큰 발급(OAuth 엔드포인트도 있음) | 관리자 > 외부 서비스 연동(API)에서 키 발급 | 가능 | 주문관리 v2 전환으로 `order_version` 파라미터 처리 필요 | 주문 데이터로 계산 |
| **고도몰** (NHN커머스) | 있음 | 제휴사키(파트너키) + 사용자키 | 개발자센터 등록("쇼핑몰직접개발" 또는 제휴사) 후 키 신청 | 조건부. 대행사가 여러 몰을 맡으려면 제휴사 등록이 필요해 보인다 | 키 발급 절차가 상대적으로 무겁다 | 주문 데이터로 계산 |

### 1-2. 스크래핑은 하지 않는다

- 판매자센터를 크롤링하려면 고객의 ID·비밀번호와 2단계 인증을 넘겨받아야 한다. 그러면 세 가지 문제가 생긴다. ① 플랫폼 약관의 계정 공유·자동 접속 금지에 걸린다. ② 계정이 정지되면 **고객 매출이 멈추고** 그 책임이 대행사로 온다. ③ 화면이 바뀔 때마다 깨진다. 1인 운영과 맞지 않는다.
- API가 없는 정산 데이터는 반자동으로 처리한다. **고객이 월 1회나 주 1회 엑셀을 공유 드라이브에 올리면 자동으로 파싱**하는 방식이다. 채널마다 엑셀 양식이 달라서, 이 파싱 작업이 오히려 AI가 쓸모 있는 지점이다(3절).

### 1-3. 통합솔루션 위에 얹는 방식 (사방넷·플레이오토)

| 솔루션 | API 조건(검색 기준) | 얻는 것 | 못 얻는 것 |
|---|---|---|---|
| 사방넷 | API 서비스 실버 **월 10만원**, API 2.0 스탠다드 월 27만원 / 프리미엄 월 48만원(본 요금제와 별도) | 수십 개 채널의 주문 수집·재고·송장·문의를 **커넥터 하나로** 받는다. 네이버·ESM·카카오 정책 문제는 솔루션사가 이미 해결해 둔 상태 | 채널별 **수수료와 정산 금액**은 기본적으로 들어오지 않는다고 봐야 한다(확인 필요) |
| 플레이오토 2.0 | BASIC 요금제 이상 + API연동 부가서비스 구매 + 개발자센터 신청(승인 2~5일) | 상품, 주문, 재고 API | 정산 |

**결론: "얹는" 방식이 이 사업의 기본 경로로 가장 현실적이다.**
- 타깃 고객(월매출 5천만~5억원, 다채널)은 이미 사방넷·플레이오토·이지어드민을 쓰고 있을 가능성이 높다. 이들의 불만은 "주문은 모였는데 **손익과 정산 대사는 여전히 엑셀**"이라는 것이고, 이 사업의 가치 제안과 정확히 겹친다.
- 구성: **주문·재고는 통합솔루션 API 1개로, 정산은 쿠팡 API + 네이버(대행사 경로 또는 엑셀) + 기타 채널 엑셀로 받는다.**
- 단점: 고객이 사방넷 API 월 10만원 이상을 추가로 낸다. 영업 메시지는 "이미 내는 사방넷에 월 10만원만 더하면 엑셀 작업이 사라진다"로 정리한다.
- 통합솔루션을 안 쓰는 소형 셀러(스마트스토어 + 쿠팡 2채널)는 쿠팡 API + 네이버 엑셀로 시작한다. 법인 전환 후에는 네이버 API대행사 경로로 바꾼다.

### 1-4. 네이버 문제의 선택지 비교

| 선택지 | 비용·시간 | 자동화 수준 | 위험 |
|---|---|---|---|
| A. 고객의 내스토어 앱 키를 받아 대행사 서버에서 호출 | 0원 | 완전 자동 | **네이버 정책 위반**(공식 답변으로 명시). 적발되면 앱이 휴면되고 고객 신뢰를 잃는다. **채택하지 않음** |
| B. 법인 설립 → API대행사 신청 | 법인 설립 실비 수십만원(셀프 등기 기준 추정) + 심사 기간 | 완전 자동. 판매자는 스마트스토어센터에서 대행사 지정만 하면 된다 | 신규·소규모 법인은 "실제 서비스로 판단하기 어렵다"는 이유로 반려될 수 있다. 고객 3~5곳 레퍼런스를 만든 뒤 신청하는 편이 유리하다 |
| C. 통합솔루션 API 경유 | 고객이 월 10만원 이상 부담 | 주문은 자동, 정산은 엑셀 | 솔루션사 API 정책에 종속된다 |
| D. 엑셀 업로드 반자동 | 0원 | 반자동(고객이 주 1회 2분 작업) | 고객이 업로드를 잊을 수 있다 → 리마인드 알림으로 보완 |

**권장 순서: D와 C로 시작한다(1~3개월). 고객 5곳을 확보하면 법인 전환과 B 신청을 진행한다(3~6개월).** 법인 전환은 세금계산서 발행과 B2B 신뢰 면에서도 이득이라, 이 사업을 계속한다면 어차피 할 일이다.

## 2. 재사용 아키텍처

### 2-1. 추천 스택: 직접 작성한 코드 (멀티테넌트 호스팅에 n8n은 쓰지 않음)

| 항목 | 추천 | 이유 |
|---|---|---|
| 언어 | **Python 3.12**(정산 대사·리포트는 pandas/polars, 커넥터는 httpx) | 정산 대사와 손익 계산이 표 연산 중심이다. Claude Code가 생성하고 테스트하기도 쉽다. TypeScript도 가능하지만 데이터 처리를 생각하면 Python이 낫다 |
| 실행 | **한국 리전 VPS 1대 + 고정 IP**(AWS Lightsail 서울 또는 Vultr 서울), Docker Compose, systemd timer/cron 또는 경량 작업 큐(APScheduler/RQ) | IP 화이트리스트(쿠팡 10개, 네이버 3개, 11번가) 때문에 고정 IP가 **필수**다. 예비 IP 1개도 처음부터 모든 고객 채널에 같이 등록해 둔다(쿠팡은 IP를 한 달에 10회까지만 수정 가능) |
| DB | **Postgres**: Supabase Pro(서울 리전) 또는 VPS 안의 Postgres + 일일 백업 | 멀티테넌트 RLS, 대시보드, 백업 기능이 기본 제공된다. Supabase Pro는 월 $25(컴퓨트 크레딧 $10 포함) |

### 2-2. 호스팅: 멀티테넌트 단일 코드베이스 (고객별 서버 분리 X)

- **코드 1벌, DB 1개로 운영하고 모든 테이블에 `tenant_id`를 두며 Postgres RLS를 적용한다.** 고객별 차이는 코드가 아니라 **설정(YAML/DB 레코드)**으로 표현한다. 채널 목록, 수수료 규칙, 원가표, 리포트 수신자, 알림 임계값이 여기에 들어간다.
- 고객별로 VPS를 나누면 15곳일 때 서버 15대를 패치·백업·모니터링해야 하고 IP도 15개를 관리해야 한다. 1인에게 맞지 않는다.
- 예외: 고객이 "우리 데이터는 우리 계정에"를 요구하면, 같은 Docker 이미지를 고객의 클라우드 계정에 배포하는 상위 요금제로 판다.
- 고객 해지 시: 데이터 내보내기(CSV/시트)와 삭제 절차를 계약서에 넣는다.

## 3. AI가 들어가는 지점과 비용

**솔직한 평가: 이 사업의 본체는 결정론적 데이터 파이프라인(ETL + 규칙)이고 LLM은 보조다.** 가장 큰 AI 레버리지는 고객에게 납품하는 기능이 아니라, **창업자가 Claude Code로 커넥터와 테스트를 빠르게 만드는 개발 생산성**이다. 영업에서는 "AI 자동화"를 앞세워도 되지만, 정산 숫자 자체는 절대 LLM이 계산하지 않게 설계한다(환각 차단).

### 3-1. 개인정보 설계 원칙 (가명처리)

개인정보를 LLM API로 보내면 **재위탁**(셀러가 창업자에게 맡긴 처리를 창업자가 LLM 공급자에게 다시 맡김)과 **국외이전**(개인정보 보호법 제28조의8)에 해당할 수 있다. Claude API는 기본이 글로벌 처리다. 그래서 다음 원칙을 둔다.

1. **보내지 않는 것**: 주문자·수령인 이름, 연락처, 주소, 개인통관고유부호, 배송메모, 주문번호 원본, 문의 본문 원문.
2. **보내는 것**: 집계값(채널·상품·일자별 매출·수수료·마진), 상품명·옵션명(개인정보 아님), 가명 토큰(`ORD_7f3a`처럼 서버 안에서만 원래 값으로 복원 가능한 값).
3. **강제 장치**: LLM 호출은 `llm/` 게이트웨이 한 곳에서만 나가게 한다. 허용 필드 화이트리스트와 정규식 PII 검사(전화번호·주소 패턴)를 통과한 데이터만 전송하고, 차단되면 로그를 남기고 호출을 중단한다.
4. **계약 문서**: 셀러와의 처리위탁 계약에 "LLM에는 개인정보를 전송하지 않으며, 가명처리된 통계만 사용"을 명시한다. 나중에 원문 처리(예: CS 문의 요약)가 필요해지면 그때 재위탁·국외이전 고지를 셀러 개인정보처리방침에 반영하고 처리 범위를 넓힌다.
5. 이 원칙을 지켜도 아래 기능은 모두 구현할 수 있다. 손익·정산 분석에 개인 식별 정보가 필요 없기 때문이다.

| 고객 수 | 계산(고정비 중앙값 7.4만원 ÷ N + 변동비 0.3만원) | 1곳당 월 비용 | 월 운영비 29만/49만원 대비 원가율 |
|---|---|---|---|
| 1곳 | 7.4 + 0.3 | **약 7.7만원** | 27% / 16% |
| 5곳 | 1.5 + 0.3 | **약 1.8만원** | 6% / 4% |
| 15곳 | 0.5 + 0.3 | **약 0.8만원** | 3% / 2% |

- **고객이 따로 부담하는 외부 비용(우리 원가 아님)**: 그 경로를 쓸 때만 사방넷 API 월 10만원 이상 또는 플레이오토 API 부가서비스. 견적서에 "고객 부담"으로 명시한다.
- **진짜 원가는 창업자의 시간이다.** 월 49만원 ÷ (주 1.25시간 × 4.3주)로 계산하면 운영 시급은 약 9.1만원이다. 장애가 한 번 나서 4시간을 더 쓰면 그달 시급은 약 5만원으로 떨어진다.

### 4-2. 셋업 소요 시간

| 작업 | 1번째 고객 | 5번째 고객(같은 채널 조합) | 비고 |
|---|---|---|---|

| 커넥터(쿠팡 API + 정산 엑셀 파서 2종 + 사방넷 또는 플레이오토) | 15~25h | 0~2h | 새 채널이면 채널당 8~20h가 더 든다(ESM·고도몰은 상단, 카페24·아임웹은 하단) |

| 온보딩: 진단 콜, 키 발급 안내, IP 등록 확인, 처리위탁 계약 | 2~3h | 1h | 문서화해 두면 고객이 혼자 한다 |

| 검증: 지난달 실제 정산과 숫자 맞추기 | 4~6h | 1~2h | 신뢰가 여기서 결정된다. 생략하지 않는다 |
| 리포트 커스터마이징 | 2~3h | 0.5~1h | |

- `02-ideas.md`의 "셋업 1건 12~20시간"은 **5번째 고객 이후에야 맞는 숫자**다. 첫 고객은 60~90시간을 각오해야 한다. 그래서 첫 고객은 할인하더라도 공통 플랫폼을 함께 만드는 **"파일럿"**으로 받는 편이 낫다.
- 5번째 고객이 새 채널(예: ESM)을 요구하면 10~20시간이 더 붙는다. 표준 지원 채널 목록을 정해 두고, 목록 밖 채널은 추가 자동화 단가(50만~150만원)로 받는다.

### 5-2. 1인 15곳: 조건부 가능

| 항목 | 주당 시간 |
|---|---|
| 정기 운영(리포트 검수, 이상 건 확인, 고객 문의) 15곳 × 0.5~0.8h | 7.5~12h |
| 장애·API 변경 대응(평균) | 3~5h |
| 키 만료·온보딩 지원 | 1~2h |
| 월 1건 소규모 개선 × 15곳 = 월 15건 × 2~3h ÷ 4.3주 | 7~10h |
| **운영 소계** | **18.5~29h** |
| 신규 셋업 월 2건 × 6~12h ÷ 4.3주 | 3~6h |
| 영업·진단 콜·콘텐츠 | 5~8h |
| **총계** | **26.5~43h** |

- 창업자가 낼 수 있는 시간은 주 30시간 이상이다. **상단 시나리오에서는 넘친다.** 가장 큰 변수는 "월 1건 소규모 개선" 약속이다. 15곳이면 매주 3~4건의 개발 요청이 쌓인다.
- **15곳을 감당하려면 네 가지가 필요하다.** ① 지원 채널과 리포트를 표준 메뉴로 고정해 커스텀을 줄인다. ② "월 1건 개선"을 "분기 1건"으로 바꾸거나 상위 요금제 전용으로 돌린다. ③ 하트비트, 만료 알림, 자동 재처리로 장애 대응을 주 3시간 이하로 낮춘다. ④ 고객 문의 창구를 하나(슬랙 커넥트 또는 카톡 채널)로 묶는다.
- 이 장치가 없으면 **현실적인 상한은 8~10곳**이다. 1~3개월 차 목표는 8곳으로 잡고, 운영 지표(주당 장애 시간, 고객당 문의 수)를 본 뒤 늘린다.

## 6. 기술적 해자: 약함~보통

| 요소 | 강도 | 설명 |
|---|---|---|
| 기술 자체 | 약함 | API 연동과 대사 로직은 크몽 판매자도 만든다. Claude Code가 이 장벽을 더 낮춘다 |
| 고객별 원가표·SKU 매핑·수수료 예외 규칙 | **보통** | 셋업 때 고객과 함께 만든 데이터라서, 옮기려면 처음부터 다시 정리해야 한다. 실질적인 전환 비용이다 |
| 매일 받는 결과물(일일 리포트·알림)에 대한 습관 | 보통 | 해지하면 내일 아침 리포트가 끊긴다. `02-screening.md`가 제안한 "결과물로 파는 운영비"와 같은 방향이다 |
| 창업자 인프라 호스팅 락인 | 보통(코드 기반일 때만) | 직접 작성한 코드나 MIT 도구로 구현해야 유효하다. n8n으로 구현하면 라이선스 문제 때문에 고객 소유 인스턴스로 옮겨야 하고, 그러면 락인이 사라진다 |
| 채널 정책 자격(네이버 API대행사, ESM 셀링툴, 카카오 연동대행사) | 보통(확보 시) | 법인과 심사가 필요해서 크몽 개인 판매자는 따라오기 어렵다. **확보하면 가장 확실한 진입장벽이다** |
| 정산 규칙 라이브러리와 회귀 테스트 | 약함~보통 | 고객이 늘수록 예외 처리가 쌓인다. 밖에서는 보이지 않는 품질 차이다 |
| 범용화 위험 | 높음 | 통합솔루션이 "손익 리포트"를 기본 기능으로 넣으면 단순 리포트 상품은 사라진다. 대응: 표준 SaaS가 못 하는 **고객별 예외 처리와 사람이 검수하는 월간 손익 해설**로 위치를 잡는다 |

## 7. 2주 실험(실험 A)에 반영할 수정사항

1. **데모는 "쿠팡 API + 스마트스토어 정산 엑셀 업로드"로 만든다.** 네이버 내스토어 키를 받아 데모하는 방식은 정책 위반이다.
2. **데모부터 직접 작성한 코드(Python)로 만든다.** n8n으로 데모를 만들면 운영 단계에서 라이선스 때문에 다시 짜야 한다.
3. 진단 콜에서 반드시 물어볼 것: ① 통합솔루션을 쓰는지, 요금제는 무엇인지(사방넷·플레이오토 API를 쓸 수 있는지) ② 채널 목록(표준 채널 밖이면 추가 견적) ③ 원가표가 있는지(없으면 셋업 시간이 2배).
4. 크몽 29만원 라이트 상품은 "1회성 스크립트 납품"으로 설계하지 않는다. **창업자 서버에서 돌아가는 1개월 체험 후 월 운영으로 전환**하는 구조로 만든다(크몽 정책 범위 안에서).
5. 1일차에 서울 리전 VPS와 고정 IP를 잡고, 쿠팡 테스트 키로 IP 등록 흐름까지 검증한다.
6. 법인 전환과 네이버 API대행사 신청은 **유료 고객 3곳을 확보한 시점**에 결정한다.
